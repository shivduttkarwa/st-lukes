# Wagtail handoff

Living document. Updated as blocks land; the Wagtail build reads this, `blocks.yaml` and `src/_includes/blocks/`.

## How the static build maps to Wagtail

| Static | Wagtail |
|---|---|
| `src/_includes/blocks/<name>.njk` | `templates/blocks/<name>.html`, the block template |
| `value.<field>` | `value.<field>` (same) |
| `{{ value.text \| safe }}` | `{{ value.text\|richtext }}` |
| `{% set img = value.image %}{% include "snippets/image.njk" %}` | `{% image value.image fill-WxH %}` |
| `{% include "snippets/button.njk" %}` | `{% include "snippets/button.html" with btn=… %}` |
| `partials/stream.njk` loop | `{% for block in page.body %}{% include_block block %}{% endfor %}` |
| `src/_data/pages/<page>.json` | the page's fields + StreamField |
| `src/_data/site.json` | site settings and snippets |
| `blocks.yaml` | the StreamField block definitions |
| `dist/assets/css/main.css`, `dist/assets/js/main.js`, from `npm run build` | copied as-is into the Wagtail static files; never edited there |

Nunjucks → Django differences to expect: `loop.index0` → `forloop.counter0`, `{% else %}` in a `for` → `{% empty %}`, `{% set %}` → `{% with %}`.

Type scale on phones and tablets: below 992 the root is the browser's own size (`font-size: 100%` in `_base.less`), so a design px is a CSS px and the visitor's text-size setting applies. From 992 the fluid root takes over, unchanged. Body copy is 16px at 1.5 line height on phones (the `--leading-body` token, Figma's 1.4 from 992), lead copy 17–18px, and nothing reads under 12px. The home and landing hero titles fit the phone's content width (`type-display-1`). Inner-hero rows may wrap under 576, so a long CMS title can't run off the screen. Phone and tablet layouts are still interpreted, until the designer's mobile frames arrive.

Headings: below 1200 a heading doesn't end on a single word where the line before can give it one (`text-wrap-style: pretty` on `h1`–`h6` in `_typography.less`); from 1200 they break as Figma does. The school's name stays on one line with a no-break space ("St Luke's", U+00A0), and a year range with a word joiner after its dash ("2029–⁠2031", U+2060), in the data's titles, labels, FAQ questions, eyebrows and short button text. Editors won't type those: in Wagtail add them in the heading templates with a small filter, or "St / Luke's" can split on a phone. The menu search drops the word joiner before matching.

Links: no `href="#"` anywhere. A link whose `url` is empty renders as an `<a>` with no `href` (`{% if card.url %} href="{{ card.url }}"{% endif %}`), so it keeps its look but goes nowhere and drops out of the tab order. Keep that test in the Django templates and never use `|default:'#'`, which treats an empty string as missing and brings `#` back. Search leaves out menu pages with no `url`.

## Site chrome

### Header and menu (`partials/header.njk`, `partials/menu.njk`)
- `site.nav` is the page tree: top-level pages in menu order; `children` are each page's live children, shown in the submenu when the parent row is clicked. A parent with no children renders as a plain link (arrow ↗); with children it is a `<button aria-expanded>` (arrow turns ↘ when open). The parent page itself is not linked in the design; add it as the first child ("Overview") if the client wants it reachable from the menu.
- For the demo, the Home submenu in `site.nav` lists every built page. It is review-only: replace it once the page tree drives the menu.
- `children[].image` is the submenu thumbnail — a page field (e.g. `menu_image`), fall back to the page's hero image. The template only writes its URL on each child link as `data-thumb`; there is one shared, decorative `<div class="menu__thumb" aria-hidden="true">` after the nav, and the script fills it. Opening a submenu shows its first child's image; switching to another top-level row cross-fades to that row's first child; hovering or focusing a child swaps to its image. The first child carries `is-current` (Nunjucks `loop.first` → Django `forloop.first`) and the script moves it with the image.
- On every screen the header bar is laid out as desktop's: Quick Links on the left, the logo centred and the menu button on the right (`1fr auto 1fr` in `_header.less`). Below 992 the logo is 80 × 94 and the Quick Links pill 176 wide; its dropdown opens from the pill's left edge, as on desktop. On a screen shorter than the list, such as a phone held sideways, the dropdown stops 14px above the bottom of the screen and scrolls inside itself, so add as many links as needed. A phone held upright (below 576) has no room for the pill beside the centred logo, so the bar is just the logo and the menu button, and Quick Links drops down from the right of the menu's Tours / Enquire / Enrol row instead (see Menu). Both are the same `snippets/quick-links.njk`: `quick_id` sets the list's id, `quick_class` adds `quick-links--desktop quick-links--light menu__quick` in the menu.
- `site.menu_links` (six small links), `site.utility_links` (Tours / Enquire / Enrol, shown in the header and again inside the panel), `site.socials` (`network` is the sprite icon id), `site.quick_links_label` (the toggle's text) and `site.quick_links` are site settings.
- The sticky header is `initStickyHeader()` in `ui.js`. It toggles `is-stuck` (fixed), `is-compact` (the navy strip with the hanging logo, beyond one header-height from the top), `is-hidden` (scrolling down) and `is-held` (GPU layers, from the first time it sticks) on `.site-header`. CSS transitions do the rest. Keep the `site-header__brand` wrapper around the logo. The entrance animation must target the outer cells and the compact bar the elements inside them, or GSAP bakes the bar's CSS moves into inline transforms. It has no CMS fields and needs nothing beyond copying `main.js` and the CSS.
- `initPlatform()` in `ui.js` adds `is-windows-chrome` to `<html>` on Chrome and Edge on Windows, and `_text-thin.less` then applies the `text-thin` filters from `partials/icons.njk` to white and gold Sanshand text (`text-thin-crisp`, a table curve, on the header row: Tours, Enquire, Enrol and the Quick Links label). They work on live text, so any wording set in Wagtail gets them. Keep `partials/icons.njk` in the base template. The Quick Links label `<span>` also carries `data-label` with the same text: on Windows Chrome a filtered white copy in its `::after` cross-fades with the navy open-state label, so keep the attribute in the template. A split title carries the filter on its `.anim-line`s while they play, because on the parent it clips their rise and delays their fade.
- Search is built from the designer's brief; Figma draws no results state. Focusing the field widens the panel and shows `site.popular_searches` in the submenu's place; typing swaps the main list for result rows (thumbnail, title, short description). `search.js` (`initMenuSearch`) filters rows rendered into a `<template data-search-index>` from `_data/search_index.js`: the built pages, the news stories, and menu-only pages with their section as the description. In Wagtail, drop the template and fetch the same `<li>` markup from a search view inside `run()`, using `search_description` for the text and a `fill-192x144` rendition for the thumbnail (the static build cuts these with `.qa/search-thumbs.py`). The form already points at `GET /search/?q=`, but the script intercepts it until then. `site.popular_searches` are plain links straight to their pages (label + url), and the client chooses which pages to list.
- Behaviour lives in `ui.js` (`initMenu`): overlay + panel slide in, panel widens to the left when a submenu opens, `inert` on the rest of the page, scroll lock with Lenis stopped, Escape and overlay click close, focus returns to the burger. The dialog role sits on the `.menu` root. The burger and close icons are a CSS `.menu-icon` (no sprite icon). On desktop it sets `--menu-zoom` so the panel fits the window height, and it numbers each list's children (`--i`) for the entrance stagger. Copy `main.js` as-is.
- The menu header never scrolls: from `lg` only the result rows scroll while search results show, and below `lg` everything under the header scrolls. The panel carries `data-lenis-prevent`, because Lenis, stopped while the menu is open, otherwise cancels wheel and touch scrolling inside it.
- Below `lg` the panel is full width and submenus open as accordions; the thumbnail is hidden. Phone layout is interpreted until the designer's mobile frames arrive.
- Below 576 the Quick Links dropdown sits at the right of the Tours / Enquire / Enrol row, inside `.menu__utility` after the links. It's desktop's pill and card (`quick-links--desktop`): a 20px label (`type-heading-6-desktop`), 54 tall, 25px insets and a 16px gap. The white card has 26px rows, the links 64 from its top, 25 in and 15 at the bottom, unfolding and fading in as on desktop. The client chose the 26px rows on touch over the site's 44px tap rule for this list. On the white panel `quick-links--light` tints the pill like the search field (`--color-black-5`) with a navy label, fading to the white card as it opens. The card carries a subtle shadow (`--color-popup-shade` / `--color-glass-shade-soft`), painted once on its own layer (`will-change: transform`). The open clip reaches 32px past the card with concentric corners, so the unfold neither repaints nor cuts it. Tried instead and dropped: a navy band behind the row, a thin royal ring, and a shadow on the pill. Below 576 the links sit 16px apart, so the pill fits beside them at 390. It fills what they leave, up to desktop's 234: 170 at 390, 210 at 430. Under 390 it takes its own row at 234. The list may reach half the gutter past a narrow pill, never off screen. Don't swap the `box-shadow` for a `filter: drop-shadow()`: that version arrived late and made the unfold janky on an iPhone. The chevron turns by a plain `rotate` here: Safari paints a transition of the registered `--quick-turn` (what the header uses) at its end value from the first frame, so it snapped. It's hidden from 576, where the pill is in the header. Escape closes an open dropdown before the menu. Desktop's fold of the middle utility links counts `a` elements only (`:first-of-type` / `:last-of-type`), so the dropdown after them doesn't change which ones fold.

## Motion conventions

Every page uses the homepage's motion, by what an element is, not where it sits. A new block picks its attributes from this list.

Until the script starts, `06-animation/_animation.less` hides everything it will reveal (`html.anim-ready`, set by the head script): reveals, split titles, sequence items, and a `data-anim-group`'s items, apart from items with their own `data-anim` and groups limited by `data-anim-media`. Under reduced motion, or if the script fails to start within 800ms, everything shows.

| Element | Motion | Markup |
|---|---|---|
| Section title (`h2`), statement | rises line by line with the scroll over 40% of the window height, the lines 0.3s apart in the timeline, so a wheel flick still shows them one by one | `data-anim="split" data-anim-type="lines"`; `data-anim-stagger` sets one split's own line gap and `data-anim-distance` its range |
| Eyebrow, lead, body copy, a lone button, a box | fades up 15px | `data-anim="reveal" data-anim-type="fade-up"` |
| Copy, buttons or arrows under or beside a title | follow the title's last line in page order, 0.15s apart (`DEFAULTS.follow` in `anim.js`), so nothing lands before the title or before what sits above it, however fast the scroll. If the title is on the first screen at load but they are below it, each keeps its own 85% trigger on the clock instead, still in page order. On phones the old own-trigger way played the lower of two stacked buttons first | add `data-anim-after-title`; on a `data-anim-group` it marks every item |
| Buttons, tabs or rows in a set, away from a title | fade up in turn | `data-anim-group="fade-up"`, with `data-anim-scroll="timed"` where two can come in at once on a phone |
| Cards (sliders, grids, campus cards) | rise 35px in whole device pixels, landing at 70% of the fade so captions never shiver, 75ms apart, on the clock | `data-anim-group="rise" data-anim-scroll="timed" data-anim-stagger="0.075"`, or `data-anim="reveal" data-anim-type="rise" data-anim-scroll="timed"` on a single card |
| Slider arrows, a button in a title row | fade up after the title, and after the title's buttons where it has them, on every screen | `data-anim="reveal" data-anim-type="fade-up" data-anim-after-title` on the arrows' wrapper, not on each arrow: a reveal leaves an inline opacity that would hide a disabled arrow's 40% |
| Photo or video frame beside copy | glides in from its side, on the clock | `data-anim-type="glide-right"` (frame on the left) or `glide-left` (frame on the right), `data-anim-scroll="timed"` |
| Logos | fade in turn | `data-anim-group="fade"` |
| Stat number | counts up from 0, its label fading in beside it | `data-anim="counter" data-anim-scroll="timed"`, `data-anim-count` on the number, `data-anim="reveal" data-anim-type="fade" data-anim-scroll="timed"` on the label |
| Gold button on a card, on hover (learning, testimonial, campus and child-page cards) | fades in over 0.35s while it grows from 80% over 0.6s, and goes in 0.35s | `.card-arrow()` on the button and `.card-arrow-shown()` in the card's hover state, both inside `(hover: hover)` |
| Curved caption on a circle | travels from the top of the circle to its place | `data-anim="reveal" data-anim-type="orbit" data-anim-scroll="timed"` on the `svg` |
| Hero | the page's own entrance (`data-anim-tier="hero"`), see each hero below | |
| Hero title rows | glide in from the window edge over 1s, 0.3s apart, on every screen; what follows starts at the title's `data-anim-landed` (1.35, or 0.75 on the landing-page hero). The `power2.out` curve is stopped at 85% (`landing()` in `anim.js`), so a row lands at about half a pixel a frame instead of creeping its last 3px over 12 frames, which made the large text shimmer. A row waits 8px past the edge already drawn, and keeps its own layer for good (`will-change: transform` in `_animation.less`): its first paint, and the outline row's SVG filter, happen before it moves, and landing never repaints it while the other row is still gliding. The entrance's clock starts on the frame after the page's scroll triggers are built. In a sequence the glide runs on the compositor (`element.animate()`, started from the GSAP timeline) on `LANDING_CURVE`, the Bézier form of the same `landing()` curve. Safari then moves the slow landing smoothly between pixels, where a GSAP-driven landing jittered on an iPhone. The row's off-screen start stays inline beneath the animation until it ends, because Chrome can draw one frame without the effect as it starts. An arriving page is not captured by the page transition (see Page transition), so the rows glide in the live page even while the circle opens | `data-anim-item="enter-left"` / `"enter-right"` in a `data-anim="sequence"` title |
| Copy on the first screen beside a hero (the homepage hero's statement, the page lead under an inner hero) | fades up as one block in the entrance, after the title and header | `data-anim="reveal" data-anim-type="fade-up" data-anim-tier="hero"` with `data-anim-order` from 2; large copy (the page lead) takes `fade-up-held`, which eases smoothly to the end |
| The same copy below 992, where it can sit under the fold | a scroll reveal at 85% instead (on the first screen it still plays straight after the entrance) | `data-anim-tier-mobile="default"` beside `data-anim-tier="hero"` |

Parallax runs as a CSS scroll-driven animation wherever the browser has one (`animation-timeline: view()`, which Chrome and Firefox 160 both take), and through ScrollTrigger elsewhere. A layer with text or hairlines (`data-anim-snap`) moves in whole device pixels: its keyframes take `--parallax-p` from 0 to 1 and the transform works out the offset from `--parallax-from` / `--parallax-to`. Don't put `var()` in the keyframes of a registered property (`@property`): Firefox can't ease it and flips it halfway. The snapped layers (home intro and pillars, the collage video and stat) jumped their whole travel, up to 366px, in one frame there. The News story swap's `--story-p` follows the same rule.

Every lift (`fade-up`, `rise`, `drop-soft`, a title's lines) moves in whole device pixels (`whole()` in `anim.js`), so a 3× phone sees 45 steps over a 15px lift, not three-pixel hops. Below 992, copy on the clock (`data-anim-scroll="timed"`) starts as its section title's last line lands and never before the copy above it, however fast the reader scrolls (`titleWait()`). A title whose copy is timed plays on the clock there too: `data-anim-scroll-mobile="timed"` on the `h2`. A `data-anim-after-title` reveal with `data-anim-scroll-mobile="timed"` leaves its title's timeline below 992 and waits on its own start line for the title's last line and the copy above, even under `data-anim-titles-first="off"`; use it where the phone stack puts the copy a screen under its title. Below 992 a scroll-linked reveal that a flick jumps ahead catches up over its own length (`SCRUB.rate`), not in the 0.4s trail, so it never pops in.

### Page transition

Every move between pages is a cross-document view transition (CSS `@view-transition`; Chrome 126+ and Safari 18.2+ play it, every other browser loads the page as it always has). No script fetches or swaps pages: each page is a whole document, so Wagtail renders pages exactly as it would without it.

- `06-animation/_transition.less` holds the choreography. The page that is leaving fades and recedes to 94% into navy over 0.5s (on a back or forward move it passes at 106% instead, so the site has depth). Meanwhile the next page opens through it in a crisp circle from the centre over 1.2s (0.8s below 992, `@vt-open-phone`) on the soft in-out curve, reaching the corners exactly at the end, the way the preloader opens. Only the leaving page is captured. The arriving page's `pagereveal` sets its root's `view-transition-name` to `none`, so there is no `::view-transition-new(root)`, and the new page draws itself beneath the transition, live, as on a fresh load. The old page's group carries the navy and a `radial-gradient` mask whose `--vt-hole` runs 0 → 100% of the way to the farthest corner, so the circle is a hole opening in the old page. iPhone Safari draws motion inside a captured page badly, and restarted an animation still running when the transition ended, so the hero must never be inside the capture. The page takes its name back in `pageswap`, to be captured as the page that leaves next. The header has no `view-transition-name` of its own. It leaves with the old page, and the circle reveals the next page's header with its hero. Named `site-header`, it was carried over on top of the circle, so the arriving page's logo, Quick Links and menu button sat over the opening instead of coming in with it. The scrollbar is the browser's own and is left alone. A page's snapshot includes its scrollbar's place, painted blank, which would recede with the page as a pale strip: the head script hands the scrollbar's width from page to page (`pageswap` stores it, every `pagereveal` sets `--page-scrollbar`, also for a page the back button restores without loading), and the leaving page's snapshot box stops that far short plus a pixel and clips (`overflow: clip` with `object-fit: none`, since a snapshot overflows its box by default). The same handover notes whether the leaving page's thumb was showing: a page left from the open menu (the scroll lock fades the thumb out) had none, so the arriving page holds its thumb transparent until the circle lands and the 0.6s colour fade in `_base.less` brings it in; from a page whose thumb was showing it is left alone. The next page's hero entrance (title rows from the window edges, statement, notice) then plays as on a fresh load, so nothing in the heroes changes for the transition.
- `transition.js` is the leaving page's side (`pageswap`). It types a back or forward move `back` and puts the root back in the capture, so the page leaves whole, header included.
- `partials/head.njk` is the arriving page's side, inline so it runs before the first frame. `pagereveal` adds `page-arrival` to `<html>`, takes the root out of the capture, and drops the preloader (the transition is the arrival). It exposes the circle's start as `window.pageOpening` (the transition's `ready`) and its end as `window.pageArrival` (`finished`), which `Anim.init` waits for before it plays the hero entrance. `<link rel="expect" href="#site-menu" blocking="render">` holds the first frame until the whole page is parsed, so the header exists when the new page is captured. Keep both in the Wagtail base template.
- `data-anim-arrival="static"` on the header means that after a transition it is already in place beneath the opening circle (`anim.js` skips its drop; the stylesheet shows it before any script runs). The attribute works on any reveal, split or sequence should a block need it.
- `data-anim-arrival="early"` on a block (News List's hero) starts the page's hero entrance as the circle starts opening, not once it has landed. That hero has no photo behind its copy, so waiting would open the circle on a bare navy panel. `main.js` passes `window.pageOpening` to `Anim.init` instead of `window.pageArrival` when the page has such a block. Below 992 every page's entrance starts halfway through the circle (0.4s into its 0.8s), so phones never wait for it to land. At the very start, an eyebrow's fade would end before the circle reached it.
- A link to a section (`/contact.html#contact-form`, `#campuses`) opens the circle on that section, not on the hero. Three things together make this work:
  - **The head script holds the first frame.** On a fresh navigation (not a reload or back/forward, where the browser restores the scroll), it adds a second `rel="expect"` for the hash, so the first frame waits until that section is parsed. It sets the root's `scroll-behavior` to `auto` until `load`, because the root's smooth scroll (`_base.less` and Bootstrap) would otherwise run down from the top past every section in between. Its `pagereveal` scrolls the target into view before the first paint, because Chrome's own jump comes a frame late.
  - **`anim.js` shows that screenful in place.** Below the top, every reveal, split and sequence in the screenful the page lands on simply shows (`landedOn`), as the circle is its entrance. Otherwise those steps would wait for the circle and leave it opening on a blank panel.
  - **Everything below reveals on scroll as usual.** At the top of a page nothing changes, so the hero entrance plays after the circle.
  Keep the head script as it is in the Wagtail base template.
- Under `prefers-reduced-motion: reduce` there is no transition: the page simply changes. Links to `#` and links off the site are untouched.

## Blocks

### hero (`blocks/hero.njk`)
- Fields in `blocks.yaml`. The background is `image` or `video` (mp4, autoplay muted loop, the image as poster). The image needs renditions at 768, 1280 and 1920 wide for the `srcset`.
- The title is two CharBlocks so the designer's two-line layout (first line flush left, second flush right) holds whatever the words are.
- `notice` is the announcement card: a teaser strip at rest, the full card on hover, focus or tap. It is a hero field for now; move it to a site setting if the client wants to change it without editing the page. The card's photo shows only on screens at least 640 tall (`@bp-tall`, a height breakpoint in `_tokens.less`). On a shorter screen below 992, such as a phone held sideways, the card opens downward over the title, as there is no room above the teaser under the header. From 576 the statement and the teaser share a row above the title, as on desktop. Below 576 the open card spans the teaser's row, so the statement doesn't show in pieces beside it. Between 992 and 1199, where the teaser sits above the title, the open card ends on the teaser's foot instead of 35 below it, so it stays clear of "HEART.". From 1200 the teaser sits beside the title's first row, which on a window narrower than Figma's 1440 comes closer in design px; the teaser and the card narrow there (`100vw` less Figma's room for them, `@hero-notice-clear`) to keep Figma's 36px from "HEART.". At 1440 and wider both are Figma's 361 and 367.
- The card fades up like the slider cards (the `rise` preset in `anim.js`): it fades in over 0.7s on `--ease-rise` (GSAP's `power2.out` as CSS) while it lifts 35px, landing at 0.49s, 70% of the fade. It closes in 0.35s and only fades under reduced motion. A Quick Links style `clip-path` unfold was tried and dropped.
- The header is site chrome (`partials/header.njk`): `site.quick_links` and `site.utility_links` from `site.json`; the logo files are `assets/icons/crest.svg` and `wordmark.svg`.
- Preloader (homepage, `p.preloader`): `base.njk` includes `partials/preloader.njk` (navy layer and rings), and `head.njk` adds `is-preloading` to `<html>` before the first paint unless the reader prefers reduced motion. It plays on every load of the homepage (set on 2026-11-03); to play it once per session instead, have `preloader.js` set a `sessionStorage` flag and test it in the head script. `preloader.js` carries the hero's own `h1` (it needs a hero block on the page): the rows slide in from the canvas edges to the screen centre, a circle mask opens on the real hero image or video, then the rows move down into place, and just before they land `Anim.init({ after })` plays the header, then the statement and notice. If `main.js` hasn't started it within 5s, the head script drops the class and the page shows normally. Keep custom properties and `var()` off `<html>` rules that switch on or off as it ends: a change on the root restyles all 1,500 elements, and on a phone the scrollbar thumb's 0.6s fade did that every frame, stalling the end of the reveal. The thumb colour, its fade and the scroll lock's gutter padding apply only under `@fine`, where a scrollbar shows.
- Preloader on smaller screens: below 992 the hole opens in 1.6s, not 2.4s (`HOLE` in `preloader.js`), to match the page transition's quicker circle there. The steps the hole times scale with it: the title starts its move into the hero at 0.93s, not 1.4s, on the same 1.6s glide, and the hero entrance follows just before it lands, so phones keep desktop's order. The rings are Figma's 750 but never more than 92% of the screen's shorter side (`min(750, 92svmin)`; 750 is 92% of Figma's 813 high screen), so they stay whole and centred on a short laptop or a phone. The centred title keeps Figma's composition wherever it fits inside `--preloader-edge` (20 design px from the screen's sides), is nudged inside where it nearly fits (375 wide phones), and where the pair is wider than the screen (1024 × 768) the rows sit flush left and right within the edge.
