# Wagtail handoff

Living document. Updated as blocks land; the Wagtail build reads this, `blocks.yaml` and `src/_includes/blocks/`.

## How the static build maps to Wagtail

| Static | Wagtail |
|---|---|
| `src/_includes/blocks/<name>.njk` | `templates/blocks/<name>.html`, the block template |
| `value.<field>` | `value.<field>` (same) |
| `{{ value.text \| safe }}` | `{{ value.text\|richtext }}` |
| `{% set img = value.image %}{% include "snippets/image.njk" %}` | `{% image value.image fill-WxH %}` |
| `{% include "snippets/button.njk" %}` | `{% include "snippets/button.html" with btn=… %}` |
| `partials/stream.njk` loop | `{% for block in page.body %}{% include_block block %}{% endfor %}` |
| `src/_data/pages/<page>.json` | the page's fields + StreamField |
| `src/_data/site.json` | site settings and snippets |
| `blocks.yaml` | the StreamField block definitions |
| `dist/assets/css/main.css`, `dist/assets/js/main.js`, from `npm run build` | copied as-is into the Wagtail static files; never edited there |

Nunjucks → Django differences to expect: `loop.index0` → `forloop.counter0`, `{% else %}` in a `for` → `{% empty %}`, `{% set %}` → `{% with %}`.

Type scale on phones and tablets: below 992 the root is the browser's own size (`font-size: 100%` in `_base.less`), so a design px is a CSS px and the visitor's text-size setting applies. From 992 the fluid root takes over, unchanged. Body copy is 16px at 1.5 line height on phones (the `--leading-body` token, Figma's 1.4 from 992), lead copy 17–18px, and nothing reads under 12px. The home and landing hero titles fit the phone's content width (`type-display-1`). Inner-hero rows may wrap under 576, so a long CMS title can't run off the screen. Phone and tablet layouts are still interpreted, until the designer's mobile frames arrive.

Links: no `href="#"` anywhere. A link whose `url` is empty renders as an `<a>` with no `href` (`{% if card.url %} href="{{ card.url }}"{% endif %}`), so it keeps its look but goes nowhere and drops out of the tab order. Keep that test in the Django templates and never use `|default:'#'`, which treats an empty string as missing and brings `#` back. Search leaves out menu pages with no `url`.

## Site chrome

### Header and menu (`partials/header.njk`, `partials/menu.njk`)
- `site.nav` is the page tree: top-level pages in menu order; `children` are each page's live children, shown in the submenu when the parent row is clicked. A parent with no children renders as a plain link (arrow ↗); with children it is a `<button aria-expanded>` (arrow turns ↘ when open). The parent page itself is not linked in the design; add it as the first child ("Overview") if the client wants it reachable from the menu.
- For the demo, the Home submenu in `site.nav` lists every built page. It is review-only: replace it once the page tree drives the menu.
- `children[].image` is the submenu thumbnail — a page field (e.g. `menu_image`), fall back to the page's hero image. The template only writes its URL on each child link as `data-thumb`; there is one shared, decorative `<div class="menu__thumb" aria-hidden="true">` after the nav, and the script fills it. Opening a submenu shows its first child's image; switching to another top-level row cross-fades to that row's first child; hovering or focusing a child swaps to its image. The first child carries `is-current` (Nunjucks `loop.first` → Django `forloop.first`) and the script moves it with the image.
- Below 992 the header bar is the logo on the left (80 × 94) and Quick Links with the menu button on the right, by grid areas in `_header.less`. The markup order is unchanged. The Quick Links pill has a set width (up to 176) and its dropdown opens right-aligned under it. From 992 it is Figma's centred logo.
- `site.menu_links` (six small links), `site.utility_links` (Tours / Enquire / Enrol, shown in the header and again inside the panel), `site.socials` (`network` is the sprite icon id), `site.quick_links_label` (the toggle's text) and `site.quick_links` are site settings.
- The sticky header is `initStickyHeader()` in `ui.js`. It toggles `is-stuck` (fixed), `is-compact` (the navy strip with the hanging logo, beyond one header-height from the top), `is-hidden` (scrolling down) and `is-held` (GPU layers, from the first time it sticks) on `.site-header`. CSS transitions do the rest. Keep the `site-header__brand` wrapper around the logo. The entrance animation must target the outer cells and the compact bar the elements inside them, or GSAP bakes the bar's CSS moves into inline transforms. It has no CMS fields and needs nothing beyond copying `main.js` and the CSS.
- `initPlatform()` in `ui.js` adds `is-windows-chrome` to `<html>` on Chrome and Edge on Windows, and `_text-thin.less` then applies the `text-thin` filters from `partials/icons.njk` to white and gold Sanshand text (`text-thin-crisp`, a table curve, on the header row: Tours, Enquire, Enrol and the Quick Links label). They work on live text, so any wording set in Wagtail gets them. Keep `partials/icons.njk` in the base template. The Quick Links label `<span>` also carries `data-label` with the same text: on Windows Chrome a filtered white copy in its `::after` cross-fades with the navy open-state label, so keep the attribute in the template. A split title carries the filter on its `.anim-line`s while they play, because on the parent it clips their rise and delays their fade.
- Search is built from the designer's brief; Figma draws no results state. Focusing the field widens the panel and shows `site.popular_searches` in the submenu's place; typing swaps the main list for result rows (thumbnail, title, short description). `search.js` (`initMenuSearch`) filters rows rendered into a `<template data-search-index>` from `_data/search_index.js`: the built pages, the news stories, and menu-only pages with their section as the description. In Wagtail, drop the template and fetch the same `<li>` markup from a search view inside `run()`, using `search_description` for the text and a `fill-192x144` rendition for the thumbnail (the static build cuts these with `.qa/search-thumbs.py`). The form already points at `GET /search/?q=`, but the script intercepts it until then. `site.popular_searches` are plain links straight to their pages (label + url), and the client chooses which pages to list.
- Behaviour lives in `ui.js` (`initMenu`): overlay + panel slide in, panel widens to the left when a submenu opens, `inert` on the rest of the page, scroll lock with Lenis stopped, Escape and overlay click close, focus returns to the burger. The dialog role sits on the `.menu` root. The burger and close icons are a CSS `.menu-icon` (no sprite icon). On desktop it sets `--menu-zoom` so the panel fits the window height, and it numbers each list's children (`--i`) for the entrance stagger. Copy `main.js` as-is.
- The menu header never scrolls: from `lg` only the result rows scroll while search results show, and below `lg` everything under the header scrolls. The panel carries `data-lenis-prevent`, because Lenis, stopped while the menu is open, otherwise cancels wheel and touch scrolling inside it.
- Below `lg` the panel is full width and submenus open as accordions; the thumbnail is hidden. Phone layout is interpreted until the designer's mobile frames arrive.

## Motion conventions

Every page uses the homepage's motion, by what an element is, not where it sits. A new block picks its attributes from this list.

| Element | Motion | Markup |
|---|---|---|
| Section title (`h2`), statement | rises line by line with the scroll over 40% of the window height, the lines 0.3s apart in the timeline, so a wheel flick still shows them one by one | `data-anim="split" data-anim-type="lines"`; `data-anim-stagger` sets one split's own line gap and `data-anim-distance` its range |
| Eyebrow, lead, body copy, a lone button, a box | fades up 15px | `data-anim="reveal" data-anim-type="fade-up"` |
| Button under a statement | follows the statement's last line | add `data-anim-after-title` |
| Buttons, tabs or rows in a set | fade up in turn | `data-anim-group="fade-up"` |
| Cards (sliders, grids, campus cards) | rise 35px in whole device pixels, landing at 70% of the fade so captions never shiver, 75ms apart, on the clock | `data-anim-group="rise" data-anim-scroll="timed" data-anim-stagger="0.075"`, or `data-anim="reveal" data-anim-type="rise" data-anim-scroll="timed"` on a single card |
| Slider arrows, a button in a title row | fade | `data-anim="reveal" data-anim-type="fade"` |
| Photo or video frame beside copy | glides in from its side, on the clock | `data-anim-type="glide-right"` (frame on the left) or `glide-left` (frame on the right), `data-anim-scroll="timed"` |
| Logos | fade in turn | `data-anim-group="fade"` |
| Stat number | counts up from 0 | `data-anim="counter" data-anim-scroll="timed"`, `data-anim-count` on the number |
| Gold button on a card, on hover (learning, testimonial, campus and child-page cards) | fades in over 0.35s while it grows from 80% over 0.6s, and goes in 0.35s | `.card-arrow()` on the button and `.card-arrow-shown()` in the card's hover state, both inside `(hover: hover)` |
| Curved caption on a circle | travels from the top of the circle to its place | `data-anim="reveal" data-anim-type="orbit" data-anim-scroll="timed"` on the `svg` |
| Hero | the page's own entrance (`data-anim-tier="hero"`), see each hero below | |
| Hero title rows | glide in from the window edge over 1s, 0.3s apart; what follows starts at the title's `data-anim-landed` (1.35, or 0.75 on the landing-page hero). The `power2.out` curve is stopped at 85% (`landing()` in `anim.js`), so a row lands at about half a pixel a frame instead of creeping its last 3px over 12 frames, which made the large text shimmer | `data-anim-item="enter-left"` / `"enter-right"` in a `data-anim="sequence"` title |
| Copy on the first screen beside a hero (the homepage hero's statement, the page lead under an inner hero) | fades up as one block in the entrance, after the title and header | `data-anim="reveal" data-anim-type="fade-up" data-anim-tier="hero"` with `data-anim-order` from 2; large copy (the page lead) takes `fade-up-held`, which eases smoothly to the end |

Every lift (`fade-up`, `rise`, `drop-soft`, a title's lines) moves in whole device pixels (`whole()` in `anim.js`), so a 3× phone sees 45 steps over a 15px lift, not three-pixel hops. Below 992, copy on the clock (`data-anim-scroll="timed"`) starts as its section title's last line lands and never before the copy above it, however fast the reader scrolls (`titleWait()`). A title whose copy is timed plays on the clock there too: `data-anim-scroll-mobile="timed"` on the `h2`.

### Page transition

Every move between pages is a cross-document view transition (CSS `@view-transition`; Chrome 126+ and Safari 18.2+ play it, every other browser loads the page as it always has). No script fetches or swaps pages: each page is a whole document, so Wagtail renders pages exactly as it would without it.

- `06-animation/_transition.less` holds the choreography. The page that is leaving fades and recedes to 94% into a navy backdrop over 0.5s (on a back or forward move it passes at 106% instead, so the site has depth), while the next page opens in a crisp circle from the centre over 1.2s on the soft in-out curve, reaching the corners exactly at the end, the way the preloader opens. The header is named `site-header` and is carried over crisp on top. The scrollbar is the browser's own and is left alone. A page's snapshot includes its scrollbar's place, painted blank, which would recede with the page as a pale strip: the head script hands the scrollbar's width from page to page (`pageswap` stores it, every `pagereveal` sets `--page-scrollbar`, also for a page the back button restores without loading), and the leaving page's snapshot box stops that far short plus a pixel and clips (`overflow: clip` with `object-fit: none`, since a snapshot overflows its box by default). The same handover notes whether the leaving page's thumb was showing: a page left from the open menu (the scroll lock fades the thumb out) had none, so the arriving page holds its thumb transparent until the circle lands and the 0.6s colour fade in `_base.less` brings it in; from a page whose thumb was showing it is left alone. The next page's hero entrance (title rows from the window edges, statement, notice) then plays as on a fresh load, so nothing in the heroes changes for the transition.
- `transition.js` is the leaving page's side (`pageswap`). It types a back or forward move `back`. A header that is stuck or under the open menu is left out of the crossfade (marked `data-vt-named`), so the next header fades in on its own rather than crossfading out of step with a compact bar.
- `partials/head.njk` is the arriving page's side, inline so it runs before the first frame. `pagereveal` adds `page-arrival` to `<html>`, drops the preloader (the transition is the arrival), clears the names a page restored from the back-forward cache still carries, and exposes the transition's end as `window.pageArrival`, which `Anim.init` waits for before it plays the hero entrance. `<link rel="expect" href="#site-menu" blocking="render">` holds the first frame until the whole page is parsed, so the header exists when the new page is captured. Keep both in the Wagtail base template.
- `data-anim-arrival="static"` on the header means that after a transition it is already in place (`anim.js` skips its drop; the stylesheet shows it before any script runs). The attribute works on any reveal, split or sequence should a block need it.
- A link to a section (`/contact.html#contact-form`, `#campuses`) opens the circle on that section, not on the hero. Three things together make this work:
  - **The head script holds the first frame.** On a fresh navigation (not a reload or back/forward, where the browser restores the scroll), it adds a second `rel="expect"` for the hash, so the first frame waits until that section is parsed. It sets the root's `scroll-behavior` to `auto` until `load`, because the root's smooth scroll (`_base.less` and Bootstrap) would otherwise run down from the top past every section in between. Its `pagereveal` scrolls the target into view before the first paint, because Chrome's own jump comes a frame late.
  - **`anim.js` shows that screenful in place.** Below the top, every reveal, split and sequence in the screenful the page lands on simply shows (`landedOn`), as the circle is its entrance. Otherwise those steps would wait for the circle and leave it opening on a blank panel.
  - **Everything below reveals on scroll as usual.** At the top of a page nothing changes, so the hero entrance plays after the circle.
  Keep the head script as it is in the Wagtail base template.
- Under `prefers-reduced-motion: reduce` there is no transition: the page simply changes. Links to `#` and links off the site are untouched.

## Blocks

### hero (`blocks/hero.njk`)
- Fields in `blocks.yaml`. The background is `image` or `video` (mp4, autoplay muted loop, the image as poster). The image needs renditions at 768, 1280 and 1920 wide for the `srcset`.
- The title is two CharBlocks so the designer's two-line layout (first line flush left, second flush right) holds whatever the words are.
- `notice` is the announcement card: a teaser strip at rest, the full card on hover, focus or tap. It is a hero field for now; move it to a site setting if the client wants to change it without editing the page.
- The header is site chrome (`partials/header.njk`): `site.quick_links` and `site.utility_links` from `site.json`; the logo files are `assets/icons/crest.svg` and `wordmark.svg`.
- Preloader (homepage, `p.preloader`): `base.njk` includes `partials/preloader.njk` (navy layer and rings), and `head.njk` adds `is-preloading` to `<html>` before the first paint unless the reader prefers reduced motion. It plays on every load of the homepage (set on 2026-11-03); to play it once per session instead, have `preloader.js` set a `sessionStorage` flag and test it in the head script. `preloader.js` carries the hero's own `h1` (it needs a hero block on the page): the rows slide in from the canvas edges to the screen centre, a circle mask opens on the real hero image or video, then the rows move down into place, and just before they land `Anim.init({ after })` plays the header, then the statement and notice. If `main.js` hasn't started it within 5s, the head script drops the class and the page shows normally.
- Preloader on smaller screens: the rings are Figma's 750 but never more than 92% of the screen's shorter side (`min(750, 92svmin)`; 750 is 92% of Figma's 813 high screen), so they stay whole and centred on a short laptop or a phone. The centred title keeps Figma's composition wherever it fits inside `--preloader-edge` (20 design px from the screen's sides), is nudged inside where it nearly fits (375 wide phones), and where the pair is wider than the screen (1024 × 768) the rows sit flush left and right within the edge. While the preloader plays the head script sets `history.scrollRestoration = "manual"`, so a reload part way down the page starts at the top with the hero instead of jumping back down under the preloader.

### page_hero (`blocks/page_hero.njk`)
- The landing-page hero (Our School): the homepage hero's frame, height, shade, header and Display 1 title, through the same `.hero` styles with a `hero--page` modifier. Fields in `blocks.yaml`.
- The title rows sit inset rather than bleeding: line 1 starts 92 in, line 2 ends 66 in. The entrance reads top down: the eyebrow fades up first (`data-anim-order="-1"`), the title rows slide in from the canvas edges as it settles (`data-anim-lead="0.2"` on the `h1`), like the homepage title (`enter-left` / `enter-right`), and the header comes in while the second row is still gliding (`data-anim-landed="0.75"` on the `h1`).
- The eyebrow (Heading 5) keeps its spaces as typed (`white-space: pre`); Figma has two between "Our" and "School".
- The image is drawn at Figma's crop (118.33% × 119.47% of the frame at −8.33%, −0.73%), so renditions are that shape: 1900 × 1083 here (`fill-1900x1083`, plus 1280 and 768 for the `srcset`). It drifts down as the homepage hero's does (`data-anim="parallax" data-anim-start="top top"`, 0 to 15% of its height while the hero leaves the window). The crop has almost no photo above the frame, but the hero's top edge leaves the window faster than the photo drifts, so the missing strip is never on screen.

### collage (`blocks/collage.njk`)
- The navy band under a landing-page hero: statement and button, portrait, video with its play pill, stat circle, quote and Instagram tile. Fields in `blocks.yaml`. Below 992 it stacks; phone layout interpreted.
- The statement rises line by line with the scroll like every split title, and its button follows the last line (`data-anim-after-title`), the same as the homepage intro.
- The quote plays the same way: the mark fades up, the words rise line by line (`data-anim="split" data-anim-type="lines"` on `.collage__words`), and the name and year follow the last line (`data-anim-after-title` on the footer). Keep the three attributes on those elements, not on the blockquote.
- The portrait's parallax moves the whole frame (`.collage__layer`), not the photo inside it, because Figma's crop fills the source's full height and leaves nothing to travel into. Rendition `fill-810x1004`.
- Parallax from 992 runs in three depths, each on Figma's spot as its centre crosses the middle of the window: the portrait and the stat circle rise ahead of the scroll (±14% and ±20% of their height, `data-anim-reverse`), and the video drifts behind it (±6%), so the circle slides over the video's corner. The statement, quote and Instagram tile stay put; the tile's foot sits under the next block, so it cannot drift down. Below 992 only the portrait moves, ±5%. Travel is `--parallax-from` / `--parallax-to` in `_collage.less` and `data-anim-speed` in the markup for browsers without scroll-driven animations; keep the two the same. The video and circle carry `data-anim-snap` so their text stays crisp, and the video's reveal and promo sit on `.collage__promo` inside the moving `.collage__video`.
- The video plays as the homepage intro's does (see `intro`), as the designer asked for this collage: muted on a loop behind the play pill once it is on screen.
- The curved caption ("Did you know?") is inline SVG text on a circle path. On the way in it travels from the top of the circle down the left side to its place, fading in, set on the arc throughout (`data-anim-type="orbit"` on the `svg`: the whole svg turns about the circle's centre from 12 o'clock, worked out from the textPath's `startOffset`, 1.6s in-out). The value counts up from 0 (`data-anim="counter"` on `.collage__circle`, as the figure carries the parallax; `data-anim-count` on the value) while its line fades in (`data-anim="reveal" data-anim-type="fade"` on the figcaption).
- The tile's foot is covered by whatever follows it, as in Figma: 2px by `page_links`, 1px by `feature_rows`. The following block needs `position: relative` to paint over it.

### page_links (`blocks/page_links.njk`)
- Child-page cards, two per row from 768 up. Each card is one link; on hover the optional `text` opens, the shade deepens and the gold arrow fades in, growing from 80% like the learning cards' (`.card-arrow()`). On touch the arrow is always shown and the text stays closed. An optional `video` plays muted on hover.
- The text opens like the learning cards: it is laid out but invisible, and the title and text sit pushed down by its height (`data-entry-more`, measured by `initEntryCards()`). On hover each slides up on its own held layer over 1s, the title first and the text 80ms later as it fades in, and back in reverse. The text travels about twice as far as on a learning card, so 1s against their 0.6s keeps the speed alike. Keep the attribute in the template.

### feature_rows (`blocks/feature_rows.njk`)
- The Alternative landing page's alternating rows: a photo flush to the window edge beside a heading, copy and a solid button. Odd rows have the photo on the left and even rows on the right, by position (`loop.index % 2` → `forloop.counter|divisibleby:2`), through CSS and the glide direction only. Below 768 each row stacks with the photo first; from 768 the photo and text sit side by side, as on desktop. Phone layout interpreted.

### inner_hero (`blocks/inner_hero.njk`)
- The inner-page hero: the header, shade and motion of `.hero`, through a `hero--inner` modifier. 772 tall at 1440: from 992 up its height is the least of Figma's ratio (53.61% of the width), Figma's 772 in design px, and the window height. The design px follow the root, which scales with the window's height as well as its width, so on a wide screen the hero stops short of the fold as it does in Figma at 1440 × 900, with the next block showing below, instead of filling the window. Measured on Contact: 772 at 1440 × 900 (122px of the next block in view), 856 at 1918 × 945 (82px), 901 at 1920 × 1080 (172px); short laptops still fill the window (711 at 1536 × 711). When a `page_lead` follows it, the hero and the lead's text share the first screen: the hero gives up the lead's top padding, its text and the same padding again below the text (`min(53.61vw, 100svh - fold)`, at least 400 design px). The rest of the lead's bottom padding, the gap before the next block, may fall below the fold, so the photo isn't squeezed for empty navy. `initHeroFold()` in `ui.js` measures the lead (`data-hero-fold` on `page_lead`) with a ResizeObserver into `--hero-fold` on the hero; until it runs, the hero assumes Figma's 296 (50 + 196 + 50). Below 992 the hero keeps its own height. The title is Display 3, gold then a 1px gold outline, inside the photo. Both rows slide in from the window's left edge, 0.2s apart (`enter-left` on each): unlike the homepage title, the second row ends on the left, so from the right it crossed nearly the whole window. `title_raised` keeps Figma's higher title on Principal's Welcome.

### page_lead (`blocks/page_lead.njk`)
- The navy band under an inner hero: a Heading 4 statement on the left and Body 1 on the right. Stacks below 992.
- It is on the first screen with the hero, so it joins the page entrance like the homepage hero's statement and notice: after the title and the header, the statement fades up as one block (`data-anim-tier="hero" data-anim-order="2"`), then the text 0.3s later (order 3). Both use `fade-up-held`: the same 15px lift as `fade-up`, landing at 55% of a 0.8s fade like it, but gliding on the paragraph's own GPU layer, held from the first frame and kept afterwards (`translate3d(0, 0, 0)`). The usual `fade-up` moves copy in whole pixels, which on text this size showed as 1px ticks; a glide that runs to the end of the fade instead creeps a fraction of a pixel per frame once the text is solid, which shivers on a 1x screen. It isn't split line by line, which is for statements the reader scrolls to. Keep the block directly under an inner hero: placed further down, it would play on load out of sight.

### staff_grid (`blocks/staff_grid.njk`)
- Heading, filter tabs and profile cards. `initFilters()` in `ui.js` matches a tab's `data-filter` against each card's space-separated `data-filter-groups` and hides the rest. The template hides the cards outside `active` on load (`{% if value.active != "all" and value.active not in person.groups %} hidden{% endif %}`: a substring test, so keep the slugs distinct words). In Wagtail, render only tabs that have people, or an empty tab shows an empty grid. The sample people are spread over every tab so each filter shows cards (All 15, Executive Team 10, Directors 9, School Council 5, Anglican Schools Corporation 4); the real groupings come from the client.
- Tabs: they rise in on the clock, 14px with a soft ease and 0.1s apart (`data-anim-group="rise-soft" data-anim-scroll="timed"`); below 992 they follow the scroll like the title and cards (`data-anim-scroll-mobile="scroll"`). The whole-pixel fade-up they had, scrubbed to the scroll, stepped each pill up at a different moment, which read as jitter. From the first change the pressed fill is a marker drawn by `.staff__tabs::before`: the script places it with `--marker-x/y/w/h` on the list (`data-filter-tabs`, keep it in the template) and it glides to the new tab over 0.35s while the text colours cross-fade; the pressed tab's own background is dropped while the marker is there (`has-marker`).
- Tab labels sit in a `span` trimmed to its capitals (`text-box: trim-both cap alphabetic`) and centred in Figma's 46px pill, so Sanshand sits in the middle at every size; keep the `span`. ### usps (`blocks/usps.njk`, card markup in `snippets/usp-card.njk`)

Behind them a navy-to-royal band, then the `background` image full-bleed with the Figma shade over it. The image starts 146 above the cards, so it holds its place whatever the heading's length.
- The card's width is rounded to whole device pixels (`round(…, var(--device-px))`, `--device-px` from `initDevicePixel()`). At a half-pixel width Chrome rounds the white card and its photo apart and a 1px white line shows beside the photo, so keep the rounding if the width changes.
- Slider: `slider.js` (`initSliders()`) turns any `[data-slider]` into a Swiper with `slidesPerView: "auto"`, keyboard and a11y on, and 900ms slides on Swiper's default `ease` with `resistance: false` (0ms under reduced motion). Card sliders (those without a `data-slider-mode`) shrink their slides with the drag speed: scale 0.925 + 0.075 × (1 − clamp((v − 0.01) / 2.99)), v in px per ms, set on each slide's `scale` every frame and eased by `transition: scale 0.4s ease-out` (`06-animation/_animation.less`). A click or release starts as a 2.5 px/ms drag that decays by 0.92 a frame. The scale is cleared when the slide lands, and none of this runs under reduced motion. Each card slide keeps its own GPU layer (`will-change: transform`), or its text jumps up to half a pixel when the scale clears. On the way in, the cards rise 35px and fade in, staggered left to right, on the clock once the slider reaches its start line. A fast scroll still shows the whole rise, where a scrubbed one ran through in a few frames. `data-anim-group="rise" data-anim-scroll="timed" data-anim-stagger="0.075"` on `.swiper-wrapper` marks each slide as a reveal, and the group passes `data-anim-scroll` and `data-anim-stagger` to them. A group's own `data-anim-stagger` is the exact gap between items (here 75ms), with no cap on the row's total, so every slider staggers alike whatever its card count. The arrows are found inside the nearest `[data-slider-scope]`. `data-slider-gap` is the gap in design px, scaled with the fluid root. The track starts on the container edge and stays `overflow: visible`, so cards run off the left of the window as it moves, as the brief asks. The last card stops on the container's right edge. Once a slider is within a screen of view, `initSliders()` switches its lazy photos to eager and decodes them, because Safari loads a lazy photo only once it is on screen and a slide arrived blank.
- Arrows: no slider loops, so Swiper disables the prev arrow on the first slide and next on the last (`disabled` on the button); disabled arrows fade to 40% (`.slider-arrow()`, and the News List hero's own gold arrows) and take no hover.
- Each card: square image (`fill-800x800`), title, text (a typed line break applies from 768 up), the gold link bar. An optional `video` plays muted on hover, as on the "Who we are" cards. The bodies are at least 176 tall, so the gold bars line up.
